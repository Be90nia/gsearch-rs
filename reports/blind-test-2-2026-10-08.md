## 新发现（已建 bd）

### gsearch-rs-6a6（P2）verify 批量丢错误分类
批量元素仅 `status/final_url/redirect_chain/ssl_valid/latency_ms` 五键。DNS 失败=0、超时=0、404=404——人读模式的 exit code 分类（3=SSL/4=DNS/5=超时）在批量（JSON 与人读表）里全丢。agent 拿到 `status:0` 无法自诊断。
**修复范式就在同仓库**：fetch 批量的 `status + message` 二元组（本盲测 T4 实测 private_blocked/error 都带 message）。对齐即可。

### gsearch-rs-w9y（P2）--read N 越界静默失败
`search "tokio" --read 99 --json` → exit 0 + 完整 SERP JSON + stderr 一行"postproc 失败: --read 99 越界（结果数 10）"。agent 合并流或只看 exit code 会当全成功。
建议：JSON 加 `read_error` 字段（对齐 content_untrusted 的做法）或 exit 1。

### 观察项（不建档）
- **P3**：read/browse 路径 stderr 有 Chrome 启动 INFO（115B）；`2>&1` 合并会污染 JSON。CLI 惯例可辩护，但 README "供 agent 消费"节应写明 **JSON 消费必须分离 stderr**（一行文档可解）。
- **P3**：dl 坏 host（DNS 不存在）仍先起 Chrome（~1s）再报错；HEAD 预检 DNS 失败可直接 fail-fast 免起浏览器。

## 亮点（修复证实有效）

1. **zc6 熔断**：盲测一 33s 黑洞 → 本次全程无一次 >3.3s search
2. **壳页指引**：stderr 给可直接复制的下一条命令——agent 自愈闭环成立（T5 实测）
3. **fetch 批量三态 + message**：全仓库批量输出的正确范式
4. **token 经济三件套**（compact-meta / excerpt / envelope v2）默认关闭零破坏，实测生效
5. **退出码语义**：doctor FAIL→1、batch 部分→1、clap 参数错→2，全部与 README 一致（盲测者自己踩的管道坑 `管道后 $?` 不算）
