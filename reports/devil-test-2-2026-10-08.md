## 二、新指控

### D2-01 [P2] 非法 gsearch.json 被静默忽略，doctor 谎报"未配置"，search 静默降级 27s

- **复现**：`echo '{"profile": TRULY_INVALID' > gsearch.json && gsearch doctor`（及 `gsearch search rust --json --limit 2`）
- **实际输出**：
  - doctor：`[SKIP] SearXNG: 未配置（GSEARCH_SEARXNG_URL / gsearch.json searxng_url），跳过`——文件**在**且配了 searxng_url，只是解析失败；doctor 说"未配置"。全部输出无任何"配置解析失败"字样（--json 与人类模式均无）。rc=1（仅因 network fail）。
  - search：26.87s 后 `error: net::ERR_CONNECTION_TIMED_OUT`，rc=1，stdout 空，stderr 无配置告警。对照：同查询配好 searxng 时 ~1-3s。即配置文件一个 JSON 手滑 = 搜索静默降级到本机不可达的 Google 直爬路径，慢 10 倍且零提示。
- **严重度主张：P2**（silent-failure 类：用户/agent 无法察觉自己处于降级态；错误消息还主动误导"未配置"）
- **契约引用**：README 配置节只写"配置文件路径（gsearch.json；不指定则依次找 ./gsearch.json、~/.gsearch/config.json）"，未定义解析失败行为；但"[SKIP] 未配置"与事实不符构成撒谎。agent 按退出码表"2 = 启动早期错误（参数、**配置**、浏览器缺失）"预期配置错误→rc=2，实测配置错误被吞、走到网络层才 rc=1。

### D2-02 [P2] browse --full --json 缺 meta.omitted 字段，README 截断契约在 browse 路径无法兑现

- **复现**：`gsearch browse https://www.gutenberg.org/files/11/11-0.txt --json --full`（151,191 字节纯文本页）
- **实际输出**：`content_text` 恰好 **50000** 字符、`meta.truncated=true`、**meta 中无 omitted 键**（fetch --json 的 meta 反而有 `omitted:0`）。对照 fetch 同页可算出被截掉 ~101,191 字符，browse 输出让 agent 无法得知丢了多少。
- **严重度主张：P2**（README 明文契约字段缺失；消费方按 README 写的 omitted 逻辑会拿到 undefined）
- **契约引用**：README L44："`--read N --json` 与 `browse` 的正文有 **HTML 源码硬截断**（默认 50000 字符……），`meta.omitted` 计的是被截掉的**标记字符数**（含标签）"——browse 实测无此字段。附带发现：--full 模式实际是"最终文本 50000 上限"（content_text 精确 = 50000），与"HTML 源码硬截断"的机制描述对不上（纯文本页上两种机制数值巧合，但字段缺失是实锤）。

### D2-03 [P2] shell quit 不退出且三处自相矛盾（上轮杠点原样复发）

- **复现**：`printf 'help\nquit\n' | gsearch shell`
- **实际输出**（管道喂入，stdin EOF 后进程才 RC=0 退出，2.33s）：
  1. banner：`进入 gsearch shell（输入 help 查命令，exit / quit / Ctrl+D 退出）`
  2. help 表：`exit / quit    提示退出；EOF / Ctrl+D 真退出`——help 自曝 quit 不真退
  3. 输入 quit 后：`退出请输入 EOF（Ctrl+D / Ctrl+Z+Enter）`——要求用户输入**另一个命令**来退出
- **严重度主张：P2**（banner 撒谎 + help 承认 + quit 响应荒诞，三处互相矛盾；上轮已杠，本轮复核 = 未修。缓解：管道/agent 场景靠 EOF 能正常退出 rc=0，伤的是交互人用）
- **契约引用**：README L104："`gsearch shell` 起一次 Chrome 后台会话，prompt `gsearch> ` 持续读 stdin"——未定义 quit 语义；banner 与 help 内部互斥。

### D2-04 [P3] `--read 0` 触发完整浏览器读阶段，0 未被拒绝也无"不读"语义

- **复现**：`gsearch search "q" --read 0`（SearXNG 命中路径，本应零浏览器纯 HTTP）
- **实际输出**：stderr 首行 `INFO 使用浏览器: Chrome -> C:\Program Files\Google\Chrome\Application\chrome.exe`，rc=0。0 被当真值处理，白烧一次 Chrome 会话。
- **严重度主张：P3**（agent 手滑 `--read 0` 的代价是一次 30s 级浏览器会话；clap 层应拒绝或定义 0=不读）
- **契约引用**：search --help 仅写"`--open / --read / --dl` 互斥"，未定义 0 值语义；M17 设计原则"SearXNG 命中全程零浏览器"被 0 值击穿。

### D2-05 [P3] `--limit 10000` 无钳制无警告，18s 连爬 28 页

- **复现**：`gsearch search rust --limit 10000 --json`
- **实际输出**：18.15s、281 条结果、rc=0、provider=searxng。上限参数直通 SearXNG 翻页循环，无"合理上限"钳制、无进度/警告输出。
- **严重度主张：P3**（诚实返回 281 条不算撒谎，但 18s 资源消耗与长 query 熔断（fix#1）的防护哲学不一致——同属"用户提供极端参数"面，一个熔断一个放行）
- **契约引用**：search --help `--limit <LIMIT>  [default: 10]`，无范围说明。

### D2-06 [P3] fetch --include 非法 selector 报错泄漏内部错误变体名

- **复现**：`gsearch fetch https://example.com --include "###" --json`
- **实际输出**：`error: CSS selector 无效: "###" (Unexpected error occurred. Please report this to the developer\EmptySelector)（用 --verbose debug 查详细）`，rc=1。
- **严重度主张：P3**（行为正确：优雅拒绝、不 panic、rc=1；但 "Please report this to the developer" + `EmptySelector` 是面向开发者的内部错误直通终端用户/agent 上下文）
- **契约引用**：fetch --help 对 --include 只写"逗号分隔 CSS selector"，未定义非法值行为（行为合格，文案失格）。

## 三、观察项（不立案）

1. **负数参数的 clap 文案**：`--read -1` / `--limit -1` / `--excerpt -5` / `--timeout -5` 一律报 `error: unexpected argument '-1' found`，不指明归属的 flag。标准 clap 行为，拒绝是正确的，文案迷惑。
2. **`--excerpt` 无 `--read` 时静默忽略**：rc=0 正常 SERP 输出。help 用 "`--read N --excerpt N`" 暗示配对，可接受。
3. **`--envelope v2` 不带 `--json`**：人类模式忽略该 flag，输出 `batch 完成：2/2 条成功`，与 help"batch --json 输出信封形态"的作用域一致。`--envelope=v2` 等号写法正常。
4. **batch + `--read` 矛盾组合**：0.01s 干净拒绝：`batch 多查询暂不支持 --read/--dl/--open（batch 无浏览器参与）；请对单查询使用`。处理正确，无浏览器泄漏。
5. **gibberish query 返回垃圾结果**（YouTube 俄语视频/Imgur）：SearXNG 上游引擎宽松匹配，非 gsearch 之过。
6. **`GSEARCH_PROFILE` 指向文件**：按 README"取末段名"语义化作 profile 名，doctor profile 检查 ok。文档一致，不立案。
7. **互斥参数**：`--read/--dl/--open`、`--excerpt/--full`、`--excerpt/--headings-only`、`--full/--headings-only` 全部 clap 层正确拒绝（rc=2）。
8. **fetch `content_untrusted:true`** 在 --json meta 中如实存在，与 README 承诺一致（好评）。
9. **`--include "#no-such-id"` 未命中回退**：include_hit=false + 全文提取正常，与 help 一致（好评）。
10. **verify --urls-file 空文件**：rc=1 + stderr `未提供任何 URL（参数为空或 urls 文件无有效行）`，非静默。rc 归 1 还是 2 可辩论，消息明确，不立案。
11. **并发 verify + fetch 双进程**：同时跑，双方 rc=0、JSON 各自完整，无互扰（好评）。
12. **doctor 在 google:443 不可达下 rc=1**：与退出码表"doctor 有 FAIL → 1"一致；FAIL 本身是已知本机网络限制，不算工具 bug。

## 四、诚实声明（没测什么 / 可能的环境假象）

1. **`--excerpt 999999` 的浏览器路径未测**：测试预算内 3 次内核超时（详见 #7）耗掉了浏览器发射额度（全程硬上限 4 次 Chrome 会话），只覆盖了 clap 解析面（-5 被正确拒绝）。excerpt 的实际钳制行为（"受 read_max_chars 总 cap 约束"）未验证。
2. **verify rc=3（SSL）/rc=5（超时）路径未触发**：需要 SSL 握手失败/稳定慢速端点；httpstat.us 属已知不稳定基础设施，未使用。`--timeout 1` 实测 example.com 0.71s 内完成（预算语义生效），超时熔断分支未观测。
3. **`status=searxng_degraded` 标记未观测**：需 SearXNG 真实半死状态；死端口测试（连接拒绝）下单查 5.62s rc=2 但 meta.status=None。黑洞性危害（33s 挂起）确认已消失，标记字段语义无法黑盒确认。
4. **batch search 部分失败 rc=1 未构造成功**：gibberish query 在 SearXNG 上游也能拿到垃圾结果（全部"成功"）；只有全死实例（rc=2）可复现。0/2 两端实测，1 靠 fetch/verify 侧面证实。
5. **dl 仅测 direct 路径**：`mode: browser`（登录墙/渲染型 URL）按浏览器预算纪律未触碰；若 direct 预检误判 HTML 页为直链，行为未知。
6. **en.wikipedia.org 被本机网络重置（WinError 10054）**：属网络环境（出口 IP 61.144.188.80），非工具问题；大页测试改用 gutenberg.org（151KB 纯文本）。
7. **三次 eval 内核超时**（配置毒化后的 search、重页 browse、shell 首测）：内核死亡可能遗留过 Chrome 孤儿/锁——已核查最终 chrome 进程数 = 0、profile 无锁文件残留后重测；shell 结论来自清理后的 bash 硬测。F2 browse 首测数据丢失，未计入任何结论。
8. **repo 根 gsearch.json 在测试中被毒化后已恢复**（内容与原值语义一致：profile=default + searxng_url）；测试产物全部落在 %TEMP%（README.md、gdl_* 目录、urls_*.txt、alice.txt、gshell_*.txt），repo 内未新增/修改除本报告外任何文件。
9. 本报告全部结论基于 debug build（743141a，v0.2.9 后 4 commits）；release exe 未测。
